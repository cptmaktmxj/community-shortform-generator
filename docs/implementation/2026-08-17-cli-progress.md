# CLI 진행 상태 표시 구현 기록

작성일: 2026-08-17

## 완료 결과

Stage 1–3 서비스에 선택형 구조화 진행 이벤트를 추가하고 CLI에서 터미널 출력기로 연결했다. 서비스 클래스를 코드에서 직접 사용할 때는 `NullProgress`가 적용되어 기존처럼 출력이 없으며, `community-shorts` CLI로 실행할 때만 `ConsoleProgress`가 활성화된다.

표시되는 상태는 다음과 같다.

- 수집: 도메인별 글 수집 중, 수집 완료, 확인·신규·중복 개수, 수집 실패, 전체 완료
- 선별: 평가 후보 개수, 후보별 선별 중, 평가 통과, 안전성 탈락, 평가 실패, 전체 완료
- 생성: 분석 중·완료·재사용, 스크립트 생성·길이 보정·완료·실패, 제목 후보 생성, 제목 심사, 제목 완료·실패, 전체 완료

각 줄에는 시각, 단계명, 현재/전체 진행률, 상태 메시지, 항목 ID 또는 집계가 표시된다. TTY에서는 청록색·녹색·빨간색으로 진행·완료·실패를 구분한다. 파일이나 파이프로 리다이렉트하면 ANSI escape code를 출력하지 않는다.

## 구현 방식

`ProgressEvent`가 단계, 상태, 메시지, 위치, 상세 정보를 표현한다. `ProgressSink` 프로토콜을 통해 `IngestService`, `CurateService`, `GenerateService`가 출력 장치와 분리된 이벤트를 발행한다.

CLI는 활성 소스 URL에서 도메인명을 추출해 수집 이벤트에 전달한다. 따라서 `geeknews` 같은 내부 식별자뿐 아니라 `news.hada.io`처럼 사용자가 인식할 수 있는 도메인이 표시된다.

외부 UI 라이브러리는 추가하지 않았다. Python 표준 출력과 TTY 판별만 사용하므로 기존 설치 크기와 실행 환경을 유지한다.

## 검증

- 출력 형식에 시각, 단계, 진행률, 메시지, 상세 정보가 포함되는지 검증했다.
- 비-TTY 출력에 ANSI 색상 코드가 섞이지 않는지 검증했다.
- 도메인별 수집 시작·완료·전체 완료 이벤트 순서를 검증했다.
- 후보별 선별 진행률과 선별 완료 이벤트를 검증했다.
- GPT 제목 모드에서 분석, 스크립트, 제목 후보, 제목 심사, 제목 완료 순서를 검증했다.
- CLI fixture 실행 결과에 분석·스크립트·제목 상태 문구가 실제 출력되는지 검증했다.

관련 진행 표시 집중 테스트는 `34 passed`를 기록했다.

마지막으로 기존 선별 결과 2건을 임시 디렉터리에 복사해 fixture 모드 CLI를 직접 실행했다. 두 항목 모두 분석, 스크립트, 제목 후보, 제목 심사, 제목 완료가 `[1/2]`, `[2/2]` 순서로 출력됐고 전체 완료 집계가 표시되는 것을 확인한 뒤 임시 디렉터리를 삭제했다. 전체 오프라인 회귀 테스트는 `110 passed, 1 deselected`를 기록했다.
